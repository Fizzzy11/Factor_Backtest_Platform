# Factor_Backtest_Platform 1.0.0 使用手册

## 1. 框架定位

本平台用于批量验证日频因子的截面排序能力，核心问题是：因子值高低排序是否能在未来 open-to-open 收益上形成稳定差异。它不是传统调仓组合回测框架。

当前产品和 Python 包版本为 `1.0.0`，distribution 名称为 `factor-backtest-platform`，导入名称为 `factor_backtest_platform`。`BacktestConfig.framework_version="v2"` 表示运行器代际，新结果目录的 `manifest.json` 继续使用独立 `schema_version="2.0"`。产品版本、运行器代际和磁盘数据结构版本含义不同。

### 版本演进

- `Factor_Backtest 2.3.0` 是经典静态报告版本，默认生成 CSV、PNG 和 HTML，保留供个人分析使用。
- `Factor_Backtest 2.4.0` 开发阶段在原项目内完成紧凑 Parquet、`latest.json`、不可变 runs、动态查询接口和按需报告改造；它是拆分前的开发过渡版本，不再作为 Classic 正式发布。
- `Factor_Backtest_Platform 1.0.0` 将上述规模化改造迁移为独立项目，作为平台版首个正式版本，默认服务批量回测和 Dashboard，并保留按需静态报告。

版本从 `1.0.0` 起步表示产品边界变化，不表示金融计算、因子时间语义或结果 Schema 回退。两个项目的 Python 包边界如下：

- Classic distribution 为 `factor-backtest`，import 为 `factor_backtest`。
- Platform distribution 为 `factor-backtest-platform`，import 为 `factor_backtest_platform`。
- 两个顶层 Python 包名不同，可以安装在统一的 `/app/workspace/zhangyuan/.venv` 中。
- 两个包可以在同一 Python 进程中同时导入；建议使用 `import factor_backtest as classic` 和 `import factor_backtest_platform as platform` 避免调用代码中的局部名称覆盖。

Dashboard 只读 Platform 结果，不重新运行回测，也不访问 ClickHouse 或原始因子数据重算指标。

### Platform 1.0.0 功能

本版本只改造项目边界、结果存储、读取和静态报告流程，不修改因子时间语义、未来收益、IC、HAC、股票池、可交易过滤、10 分组、风险行业或外部收益计算口径：

- 每次成功回测只保存一个不可变 `runs/<run_id>/`，`latest.json` 指向最新成功 run，不再复制实体 `latest/`，也不依赖软连接。
- run 先写入 `runs/.staging/<run_id>/`，核心模块和 Parquet 校验成功后原子发布；同一因子的发布使用文件锁串行化。
- 每类日度基础表跨股票池合并为一个压缩 Parquet，通过 `pool` 列区分。默认使用 `zstd`。
- 累计 IC、20 日均线、年度 IC、窗口分组收益、多空和绩效表改为从日度基础表动态派生，不再为每个 pool 重复保存大量 CSV。
- 新增 `ic_view()`、`group_return_view()`、`quality_view()`。选择日期后累计 IC 从 0 开始，累计分组收益从 1 开始，统计值按所选区间重新计算。
- `run_factor_backtest_data()` 不生成 PNG 和 HTML；`render_factor_backtest_report(run_dir)` 可随时从 Parquet 重建完整静态报告。
- `run_factor_backtest()` 默认不生成 PNG 和 HTML；显式设置报告开关或调用 `render_factor_backtest_report()` 可按需重建。
- 旧 `<factor>/latest/` 和 CSV 结果继续可读，但不会自动迁移、删除或覆盖。

## v2.3.0 更新内容

本次更新重点修正多日重叠远期收益的统计解释，并增加年度 IC 跟踪。因子日期语义、open-to-open 收益公式、每日滚动计算频率、股票池、可交易过滤、10 分组和外部收益对齐方式均保持不变：

- IC 和多空均值新增 Newey-West HAC t-stat；内置 h 日收益默认使用 `lag=h-1`。
- IC 统计新增未年化 `icir_raw`、普通 `t_stat_naive`、修正后的 `t_stat_hac`、`hac_lag`、`valid_days` 和状态字段。
- 多空统计新增未年化 `mean_over_std_raw`，报告不再把旧 `sharpe=mean/std` 解释为年化 Sharpe。
- 新增 `yearly_ic` 模块，按因子日自然年输出年度 IC 表和趋势图，并支持最小有效天数及不完整年份开关。
- 多空累计图改为从 G10、G1 分别转换得到的日等效 spread 诊断曲线，不再把原始 h 日重叠收益直接当作每日组合收益。
- `h>1` 不再报告可实现组合最大回撤；`diagnostic_max_drawdown` 为 `NaN`，并标记 `overlapping_forward_returns`。
- 原换手率输出明确解释为每日分组成员变化率，新增 `group_membership_change_*` 表名并保留旧文件名兼容。
- HTML report 已接入年度 IC、HAC 统计、日等效多空曲线、回撤适用性和成员变化率说明。
- 旧 `icir`、`t_stat`、`sharpe`、`max_drawdown`、`group_turnover_*` 字段或文件名暂时保留，便于和历史结果及现有下游脚本对比。

## v2.2.3 更新内容

本次是向后兼容的因子输入格式扩展，不改变回测时间语义、open-to-open 收益计算、股票池、可交易过滤或统计逻辑：

- 因子输入支持 `.parquet`，并推荐正式生产因子优先保存为 parquet。
- 默认因子发现顺序为 `.parquet`、`.h5`、`.csv`，同名多格式文件同时存在时优先读取 parquet。
- parquet 支持单文件宽表、单文件长表，以及后缀为 `.parquet` 的按月或按年分区目录。
- 标准因子矩阵仍为 `trade_date × symbol`，`trade_date` 为日频 `DatetimeIndex`，`symbol` 为字符串列名。
- 加载阶段保留 `NaN`、`Inf`、`-Inf`，不做填充、缩尾、标准化或方向翻转；这些非有限值会在后续有效样本筛选中被排除。
- 分区 parquet 目录只读取直接子级 `*.parquet` 文件，忽略 `manifest.json` 和其他非 parquet 文件；分区日期不能重叠。日频因子需要每日追加时，推荐按月分区，以减少更新当前数据时的重复 I/O。

## v2.2.2 更新内容

本次是小版本修复，重点修正 CSV 宽表读取时的日期列识别问题：

- 因子 CSV 宽表支持显式 `date` 或 `trade_date` 列，框架会把该列设为 `trade_date` index。
- 外部收益 CSV/宽表也支持显式 `date` 或 `trade_date` 列，处理方式与因子宽表一致。
- 仍兼容日期已经在 DataFrame index 中的标准宽表，以及长表/MultiIndex 长表。
- 新增回归测试覆盖因子宽表和外部收益宽表的日期列解析。
- 该修复解决了类似 `factor_macd_delta.csv` 这种 `date,000001.XSHE,...` 文件读入后日期错位、回测结果全空的问题。

## v2.2.1 更新内容

本次是小版本优化，重点补齐公司侧正式 diagnostics 输出流程：

- 新增 `CompanyDiagnosticsConfig`，用于控制正式公司侧诊断输出，默认 `enabled=False`。
- 正式 diagnostics 和 `HandoffConfig` 的第一轮验收样例包分离；正式流程只在真实计算成功时写 `status="computed"`。
- 在 Platform 1.0.0 的 Schema 2 结构中，打开后只在当前不可变 run 的 `diagnostics/` 下输出最多四个 JSON；`latest.json` 会指向该 run，不再复制第二份 diagnostics。
- 支持 production book、peer book 和 regime 布尔宽表输入；当前 file/csv/parquet 已实现，ClickHouse source、`factor_meta_path`、`factor_ls_pnl_path` 为后续预留。
- `examples/run_factor_dm_20d.py` 增加 `company_diagnostics_enabled` 开关和完整参数示例；保持 `False` 时不读取 book/regime，也不写正式 `diagnostics/`。
- 使用手册新增正式 diagnostics 的输入格式、参数表、计算口径和写文件规则。

## v2.2.0 更新内容

本次更新重点是增加公司平台 handoff 交付包导出流程。它用于把一次真实 Factor_Backtest 运行结果整理成平台第一轮验收要求的 `sample_latest/`，证明单因子文件能够跑出真实、非空、机器可读、可复现的交付样本。

主要变化：

- 新增 `HandoffConfig` 配置项，默认 `enabled=False`，不会影响普通回测输出。
- 打开 `handoff.enabled=True` 后，框架会在真实回测结束后额外生成 `docs/handoffs/factor_backtest_platform/`。
- 交付目录包含 `README.md`、`platform_schema_notes.md`、`factor_backtest_commit.txt` 和 `sample_latest/`。
- `sample_latest/` 内包含平台要求的 `run_meta.json`、`run_log.json`、5 张核心 CSV 和 4 个 diagnostics JSON。
- 5 张核心 CSV 由真实 run 的内存 section 结果导出，包括 IC 统计、分组收益、绩效指标、边际组成员变化和数据质量，不依赖通用结果目录继续保存重复 CSV。
- 导出器会校验核心 CSV 是否存在、是否非空，并校验 `ic_stats_spearman.csv` 是否覆盖当前 `horizons` 对应的 `1d/5d/10d/20d` 等 IC 统计。
- 第一轮尚未计算的 `spanning`、`crowding`、`mechanism_consistency`、`diversity` 会以 `pending(company)` JSON 写出，并明确原因、负责人、所需输入和下一步。
- `examples/run_factor_dm_20d.py` 增加 `handoff_enabled`、`handoff_factor_direction` 和 `handoff_data_asof` 示例参数。
- 新增 handoff 测试，覆盖默认关闭、成功导出和 IC horizon 缺失时拒绝导出。

因子标准输入为宽表：

```text
index = trade_date
columns = symbol
values = factor value
```

CSV/parquet 宽表可以使用显式日期列：

```text
date/trade_date, 000001.XSHE, 000002.XSHE, ...
```

框架会自动将 `date` 或 `trade_date` 列转为 `trade_date` index。

`factor_df.loc[t]` 表示 `t` 日收盘后生成、下一交易日开盘前可用于交易的因子值。未来收益按：

```text
future_return_h[t] = open_price[t+h+1] / open_price[t+1] - 1
```

这里的 `t+1`、`t+h+1` 都是交易日序列上的偏移，不是自然日偏移。

## 3. 常用路径

```python
project_dir = "/app/workspace/zhangyuan/Factor_Backtest_Platform"
data_root = "/data/zhangyuan"
pool_dir = "/data/zhangyuan/pool"
output_root = "/data/zhangyuan/Factor_Backtest_Platform_Result"
```

Platform 和 Classic 只读共享 `/data/zhangyuan` 下的因子、行情和股票池输入，不复制数据库数据。Dashboard 默认读取 `/data/zhangyuan/Factor_Backtest_Platform_Result`，不得读取 Classic 输出目录作为正式 Platform 数据源。

默认因子文件发现规则：

```text
/data/zhangyuan/factor_dm_20d/factor_dm_20d.parquet
/data/zhangyuan/factor_dm_20d/factor_dm_20d.h5
/data/zhangyuan/factor_dm_20d/factor_dm_20d.csv
```

`factor_dm_20d.parquet` 可以是单个 parquet 文件，也可以是后缀为 `.parquet` 的分区目录。日频因子生产推荐使用月度分区：

```text
/data/zhangyuan/factor_order_imbalance_v1/
  manifest.json
  factor_order_imbalance_v1.parquet/
    2026-01.parquet
    2026-02.parquet
    2026-03.parquet
```

每个月度文件保存当月所有交易日的日频因子。每日更新时只需读取并重写当月文件，无需重写全年数据。读取时只扫描该目录的直接子级 `*.parquet` 文件，按文件名排序后逐个标准化并按 `trade_date` 合并。不同分区股票列可以不完全一致，框架会取列并集；不同分区不能包含重复 `trade_date`。

月度和年度分区的回测计算口径完全相同。当前回测加载时仍会读取目录内全部分区文件，因此月度分区优化的是因子日常写入开销，不是按回测日期范围裁剪读取量。

单文件 parquet 用法：

```python
from factor_backtest_platform.factor_loader import load_factor_file

factor_df = load_factor_file(
    "/data/zhangyuan/factor_order_imbalance_v1/factor_order_imbalance_v1.parquet"
)
```

分区 parquet 目录用法相同，只需要把路径指向后缀为 `.parquet` 的目录：

```python
factor_df = load_factor_file(
    "/data/zhangyuan/factor_order_imbalance_v1/factor_order_imbalance_v1.parquet"
)
```

支持的因子文件格式包括：

- CSV：宽表或长表。
- H5：宽表或长表，`h5_key` 只对 H5 生效。
- parquet：单文件宽表、单文件长表、按月或按年分区目录；日频因子持续更新时推荐按月分区。

长表字段兼容 `trade_date/date`、`symbol/asset`、`factor_value/factor/value`；如果因子值列使用其他名称，可以在 `load_factor_file(..., value_column="自定义列名")` 中显式指定。

加载完成后的标准矩阵为：

```text
index.name = "trade_date"
index      = DatetimeIndex，日期升序且唯一，无日内时间
columns.name = "symbol"
columns      = 字符串股票代码，升序且唯一
values       = 单个因子的数值，NaN/Inf/-Inf 原样保留
```

`NaN`、`Inf`、`-Inf` 会保留到标准矩阵和数据质量统计中，但不会进入有效 IC、分组收益和多空收益样本。

## 4. BacktestConfig 参数

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `framework_version` | `"v2"` | 运行器输出代际，写入 `run_meta.json`；磁盘结构另见 `manifest.schema_version` |
| `output_root` | `/data/zhangyuan/Factor_Backtest_Platform_Result` | Platform 回测结果根目录 |
| `factor_name` | `None` | 输出目录使用的因子名 |
| `selected_pools` | `["all"]` | 股票池列表，`all` 表示全市场；示例脚本默认跑 `["all", "hs300_pool", "zz1000_pool", "zz2000_pool"]` |
| `horizons` | `[1, 5, 10, 20]` | open-to-open 未来收益周期 |
| `horizon_colors` | 柔和蓝橙绿红 | 图表中 1D/5D/10D/20D 颜色 |
| `min_listed_days` | `120` | 新股/次新股过滤阈值 |
| `tradability_filter` | `True` | 是否执行涨跌停、ST、停牌、新股过滤 |
| `ic_methods` | `["spearman"]` | IC 相关系数方法，可选 `["spearman"]`、`["pearson"]` 或 `["spearman", "pearson"]` |
| `min_ic_stocks` | `30` | 每日 IC 最小有效股票数 |
| `min_group_stocks` | `10` | 每日分组收益最小有效股票数 |
| `min_industry_ic_stocks` | `10` | 行业内分组时每个行业每日最小有效股票数 |
| `analysis_windows` | `[120, 250, 750]` | 预留分析窗口参数 |
| `yearly_ic_min_days` | `60` | 每个“自然年 × 收益标签”输出年度 IC 统计所需的最小有效 IC 天数 |
| `yearly_ic_include_partial_year` | `True` | 是否保留回测首尾可能不完整的自然年；表中用 `is_complete_year` 标识 |
| `group_return_windows` | `{"6m":120,"1y":250,"3y":750,"5y":1250}` | 分层收益统计窗口 |
| `enabled_sections` | `"all"` | 输出模块列表，或 `"all"` |
| `output_layout` | `"latest_runs"` | 默认保存不可变 `runs` 并写 `latest.json`；`"timestamp"` 保留无 latest 索引的兼容布局 |
| `artifact_level` | `"none"` | artifacts 保存级别；`"none"` 不写中间矩阵，`"full"` 写完整中间结果 |
| `render_plots` | `False` | 当 `export_static_report=True` 时是否生成 PNG；显式设为 `True` 可生成完整图片 |
| `export_static_report` | `False` | 是否在回测当次生成 HTML/PNG；Platform 默认使用数据模式 |
| `parquet_compression` | `"zstd"` | Schema 2 基础结果压缩，可选 `"zstd"`、`"snappy"`、`"gzip"`、`"none"` |
| `write_neutralized_factors` | `False` | 是否在 `artifacts/<pool>/` 写完整风格/行业中性化 residual 因子矩阵 |
| `handoff` | `HandoffConfig(enabled=False)` | 平台交付包导出配置；默认关闭，打开后在真实回测结束后额外生成 `docs/handoffs/factor_backtest_platform/` |
| `verbose` | `True` | 是否打印轻量进度日志 |

```python
from factor_backtest_platform import BacktestConfig, run_factor_backtest

cfg = BacktestConfig(
    factor_name="factor_dm_20d",
    selected_pools=["all"],
    horizons=[1, 5, 10, 20],
```

## 6.1 平台 handoff 交付包

如果需要按公司平台验收任务书生成第一轮最小闭环交付包，可以打开 `HandoffConfig`。该开关不会改变正常 `latest/` 和 `runs/` 输出，只会在真实回测完成后额外复制和整理一份 handoff 目录。

推荐第一轮 handoff 使用最小必需模块：

```python
from factor_backtest_platform import BacktestConfig, HandoffConfig, run_factor_backtest
from factor_backtest_platform.config import DataSourceConfig

cfg = BacktestConfig(
    factor_name="smoke_factor_v1",
    selected_pools=["all"],
    horizons=[1, 5, 10, 20],
    ic_methods=["spearman"],
    data_sources=DataSourceConfig(risk_exposure_source="none"),
    enabled_sections=[
        "data_quality",
        "cumulative_ic",
        "group_return",
        "long_short",
        "group_turnover",
        "performance_metrics",
    ],
    handoff=HandoffConfig(
        enabled=True,
        factor_direction="high_is_long",
        data_asof="2026-06-10",
    ),
)

result = run_factor_backtest(
    factor_df=factor_df,
    market_data=market_data,
    config=cfg,
)

print(result.handoff_dir)
```

默认生成目录：

```text
docs/handoffs/factor_backtest_platform/
  README.md
  platform_schema_notes.md
  factor_backtest_commit.txt
  sample_latest/
    run_meta.json
    run_log.json
    pools/
      all/
        tables/
          ic_stats_spearman.csv
          group_return_summary.csv
          performance_metrics.csv
          group_turnover_edge_summary.csv
          data_quality.csv
    diagnostics/
      spanning.json
      crowding.json
      mechanism_consistency.json
      diversity.json
```

导出器会校验 5 张核心 CSV 是否存在且非空。如果缺少 `cumulative_ic`、`group_return`、`long_short`、`group_turnover`、`performance_metrics` 或 `data_quality` 中的必要输出，会直接报错，不会生成伪造指标。四类 diagnostics 第一轮默认写为 `pending(company)`，原因、owner、required_input 和 next_step 会写入 JSON。

`HandoffConfig` 常用参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `False` | 是否导出 handoff 包 |

## 6.2 外部收益数据

默认会使用 `horizons=[1, 5, 10, 20]` 生成内置 open-to-open 未来收益。如果要额外加入自定义收益，在调用 `run_factor_backtest` 时传入 `external_returns`：

```python
result = run_factor_backtest(
    factor_df=factor_df,
    market_data=market_data,
    config=cfg,
    external_returns={
        "my_return": {
            "data": "/data/zhangyuan/external_returns/my_return.csv",
            "horizon_days": 5,
        },
    },
)
```

外部收益宽表要求：

```text
index = trade_date
columns = symbol
value = future return
```

CSV 宽表也可以使用显式日期列：

```text
date/trade_date, 000001.XSHE, 000002.XSHE, ...
```

框架会自动将该列作为 `trade_date` index。

其中 `external_return.loc[t, symbol]` 必须表示用于检验 `factor_df.loc[t, symbol]` 的未来收益。`horizon_days` 只影响 10 组累计收益线图，不影响 IC、分组平均收益、多空收益等核心统计。

如果只想使用外部收益，不计算内置 1D/5D/10D/20D，可以把 `horizons` 设为空列表：

```python
cfg = BacktestConfig(
    factor_name="factor_dm_20d",
    selected_pools=["all", "hs300_pool", "zz1000_pool", "zz2000_pool"],
    horizons=[],
    ic_methods=["spearman"],
)

result = run_factor_backtest(
    factor_df=factor_df,
    market_data=market_data,
    config=cfg,
    external_returns={
        "my_return": {
            "data": external_return_df,
            "horizon_days": 5,
        },
    },
)
```

即使 `horizons=[]`，当前接口仍需要传入 `market_data`，因为框架还会用行情日期和股票列做对齐、股票池和可交易性过滤。

## 6.3 风格暴露和行业数据

如果需要输出风格暴露相关性、行业内分组收益、风格中性化 IC、风格+行业中性化 IC，需要提供日度风险暴露和行业数据。

默认本地风险暴露文件路径建议为：

```text
/data/zhangyuan/risk&industry/CNE5_Industry_daily.parquet
```

配置方式：

```python
from factor_backtest_platform.config import BacktestConfig, DataSourceConfig, PathConfig

cfg = BacktestConfig(
    paths=PathConfig(
        data_root="/data/zhangyuan",
        risk_exposure_path="risk&industry/CNE5_Industry_daily.parquet",
    ),
    data_sources=DataSourceConfig(
        risk_exposure_source="csv",
    ),
    enabled_sections="all",
    artifact_level="none",
    write_neutralized_factors=False,
)
```

`risk_exposure_path` 可以是绝对路径，也可以是相对 `data_root` 的路径。`risk_exposure_source="csv"` 是历史保留的本地文件读取入口，当前支持 `.parquet` 和 `.csv`；默认 parquet 读取依赖 `pyarrow`。未来如果该数据入库，保留 `risk_exposure_source="clickhouse"` 和 `ClickHouseTableConfig.risk_exposure` 作为统一切换入口，ClickHouse 版本目前会明确报未实现。

本地文件支持 `date` 或 `trade_date` 日期列，也支持把日期作为保存后的第一列。必需字段：

```text
symbol
size
non_linear_size
momentum
liquidity
book_to_price
leverage
growth
earnings_yield
beta
residual_volatility
行业 dummy columns
```

行业信息也可以使用单列 `industry`，每个 `date-symbol` 填一个行业名或行业码，例如 `0..30` 或 `801760.INDX`。这是推荐格式；数字行业码会按数值排序，字符串行业码按文件中首次出现顺序保留。使用单列 `industry` 时，每个 `date-symbol` 只属于一个行业，框架会在行业内分组收益中优先使用 compact industry code 快路径，并在需要行业回归或行业暴露时生成内部 dummy。使用 one-hot 行业列时，多个行业为 1 的股票仍会同时参与这些行业的计算。

`comovement` 当前会被读取器忽略，不进入默认 Barra10 风格暴露。行业归属按每日 `date-symbol` 动态使用，不假设某只股票永久属于某个行业。如果某日某股票没有任何行业归属，在需要行业信息的计算中剔除并给 warning；如果 one-hot 格式下多个行业 dummy 为 1，该股票会同时参与这些行业的计算，并使用兼容路径。

默认 `risk_exposure_source="csv"`，所以只要文件存在，`enabled_sections="all"` 会运行以下模块：

```text
factor_style_exposure
style_neutralized_ic
style_industry_neutralized_ic
group_exposure_diagnostics
within_industry_group_return
group_turnover
```

其中 `group_turnover` 不依赖风险暴露数据；即使设置 `risk_exposure_source="none"`，`enabled_sections="all"` 仍会输出分组换手率。其余列出的风格、行业、中性化模块依赖 `risk_exposure`。

如果当前环境没有风险暴露文件，需要显式关闭：

```python
cfg = BacktestConfig(
    data_sources=DataSourceConfig(risk_exposure_source="none"),
)
```

关闭后，`enabled_sections="all"` 不会运行这些依赖风险暴露数据的模块，会保留基础因子回测输出和不依赖风险暴露的 `group_turnover`。

主要输出：

```text
factor_style_exposure_corr_spearman / pearson
factor_style_exposure_corr_summary_spearman / pearson
factor_style_exposure_corr_spearman.png / pearson.png

style_neutralized_ic_spearman / pearson
cumulative_style_neutralized_ic_spearman / pearson
style_neutralized_ic_stats_spearman / pearson
cumulative_style_neutralized_ic_spearman.png / pearson.png
style_neutralized_factor  # 仅 write_neutralized_factors=True 时输出

style_industry_neutralized_ic_spearman / pearson
cumulative_style_industry_neutralized_ic_spearman / pearson
style_industry_neutralized_ic_stats_spearman / pearson
cumulative_style_industry_neutralized_ic_spearman.png / pearson.png
style_industry_neutralized_factor  # 仅 write_neutralized_factors=True 时输出

within_industry_daily_group_returns
within_industry_group_return_summary
within_industry_group_return_bar.png
within_industry_group_cumulative_return_1d/5d/10d/20d.png

group_style_exposure_daily
group_style_exposure_summary
group_industry_exposure_daily
group_industry_exposure_summary
group_industry_exposure_plot_label_map
group_style_exposure_g1/g10/g10_minus_g1/g1_minus_pool/g10_minus_pool.png
group_industry_exposure_g1/g10/g10_minus_g1/g1_minus_pool/g10_minus_pool.png

daily_group_turnover
group_turnover_summary
group_turnover_edge_summary
daily_group_membership_change
group_membership_change_summary
group_membership_change_edge_summary
group_turnover.png
group_turnover_edges.png
```

风格中性化因子值是每日截面等权 OLS 回归后的 residual：

```text
factor = intercept + Barra10 style exposures + residual
```

风格+行业中性化因子值是：

```text
factor = intercept + Barra10 style exposures + industry dummies + residual
```

中性化 IC 默认直接在日度 OLS residual 上计算，不再默认写出完整 residual 因子矩阵，以减少大表写入时间。若需要检查或复用 residual 因子值，可以在配置中设置 `write_neutralized_factors=True`，此时会额外输出 `style_neutralized_factor` 和 `style_industry_neutralized_factor`。

所有中性化和新增统计仍然按每个 pool 独立计算，并使用 `valid_mask` 过滤后的股票。
`group_exposure_diagnostics` 每天先在当前 pool 的 `valid_mask` 有效股票内按因子值分 G1-G10，再输出 pool、G1、G10、G10-G1、G1-pool、G10-pool 的风格暴露和行业暴露。G1 是因子值最低组，G10 是因子值最高组；因为框架不自动判断因子正负方向，所以这部分会同时关注 G1 和 G10。
行业列通常是中文名。为了避免服务器缺中文字体时 Matplotlib 反复 warning，行业暴露图会使用 `industry_01` 这类 ASCII 图例；真实行业名保存在 `group_industry_exposure_plot_label_map`。
`group_turnover` 实际计算的是相邻因子日同一分组的成员变化率：`1 - |previous ∩ current| / |current|`。它额外汇总 G1、G10 和 `edge_avg`，其中 `edge_avg` 是两端成员变化率的简单平均。该指标按因子日逐日计算，不考虑 horizon、持仓权重漂移、分层资金或交易成本，因此不能解释为可交易组合的真实换手率。新表使用 `group_membership_change_*` 命名；旧 `group_turnover_*` 表名和图片文件名保留一个兼容周期。
风险暴露数据在每个 pool 内会先对齐成内部矩阵缓存，供 `factor_style_exposure`、中性化 IC、`group_exposure_diagnostics` 和 `within_industry_group_return` 复用。panel 会同时保留行业 dummy 矩阵和 compact industry code：中性化 IC、行业暴露诊断继续使用 dummy 口径；行业内分组收益在没有多行业重复归属时使用 code 分组，避免 `date × horizon × 行业数` 的重复全股票扫描。这个优化不改变用户配置、输出表名或图名。

默认输出结构如下。`runs/<run_id>/` 的时间戳固定使用中国时区 `Asia/Shanghai`：

```text
/data/zhangyuan/Factor_Backtest_Platform_Result/factor_dm_20d/
  latest.json
  runs/
    .staging/
    20260520_093000_000000/
      manifest.json
      run_meta.json
      run_log.json
      data/
      plots/        # 仅生成静态报告时存在
      report.html   # 仅生成静态报告时存在
      artifacts/    # 仅 artifact_level="full" 时存在
```

`latest.json` 只保存 run_id 和因子目录内的相对路径，不复制数据、不使用软连接。下游应调用 `load_backtest_result(..., run="latest")` 解析它；历史追溯传入具体 run_id。

## 10. 输出说明

Schema 2 单次 run：

```text
manifest.json
run_meta.json
run_log.json
data/                    # 跨 pool 合并的压缩日度基础表
plots/<pool>/            # 仅静态报告生成时存在
report.html              # 仅静态报告生成时存在
artifacts/<pool>/        # 仅 artifact_level="full" 或 residual 显式输出时存在
diagnostics/             # 仅公司诊断启用且成功计算时存在
```

`manifest.json` 记录 Schema 版本、表路径、行数、列名、索引列、股票池、日期范围、压缩方式和模块状态。每个基础 Parquet 都包含显式 `pool` 列；加载器读取后恢复原 DataFrame 索引。

默认 `artifact_level="none"`，不会写 `aligned_factor`、`valid_mask`、`future_returns_*` 等完整矩阵，但每日 IC、每日分组收益和数据质量等结果仓库基础数据始终保存。需要排查数据对齐时设置 `artifact_level="full"`。

`export_static_report=True` 且 `render_plots=True` 时生成 PNG 和 HTML。`export_static_report=False` 时不生成两者；之后调用 `render_factor_backtest_report(run_dir)` 会从压缩 Parquet 在同一不可变 run 下生成 `plots/<pool>/` 和 `report.html`，不会重新写重复 CSV。

同一因子的 run 发布由文件锁串行化。只有完整成功的 staging 才会原子移动到 `runs/<run_id>/` 并更新 `latest.json`。可选风险诊断失败会记录状态后允许发布；已启用的 `data_quality`、`cumulative_ic`、`group_return` 失败时拒绝更新 latest。
`run_log.json` 会保存 `timings` 字段，用于性能跟踪。结构包括全局耗时、每个 pool 的准备/核心计算/写 artifacts 阶段耗时，以及每个 section 的 `compute_seconds`、`render_seconds`、`write_seconds` 和 `total_seconds`；当 `artifact_level="none"` 时，写 artifacts 阶段通常接近 0。

## 11. 主要指标口径

IC 方法：默认只计算 Spearman RankIC。可以通过 `BacktestConfig(ic_methods=["pearson"])` 只计算 Pearson IC，或通过 `BacktestConfig(ic_methods=["spearman", "pearson"])` 同时计算两种 IC。Spearman 衡量排序相关性，Pearson 衡量原始因子值与未来收益值的线性相关性。每日有效股票数低于 `min_ic_stocks` 时，该日该收益标签的 IC 记为 `NaN`。

RankIC：每日截面因子 rank 与未来收益 rank 的 Spearman 相关。因子日 `t` 对应的收益是下一交易日开盘买入、持有 `horizon` 个交易日后开盘卖出。

累计 IC：每日 IC 的累计和。

IC 显著性：报告默认使用 Newey-West HAC t-stat 修正重叠窗口造成的序列相关。内置 h 日收益默认使用 `lag=h-1`，因此 1D/5D/10D/20D 分别使用 `0/4/9/19`；外部收益使用显式 `horizon_days-1`。未提供 `horizon_days` 的外部收益仍计算每日 IC 和均值，但 `t_stat_hac` 为 `NaN` 并给 warning。`t_stat_naive` 和兼容字段 `t_stat` 保留普通独立样本口径，便于与历史结果对比，不应作为多日重叠收益的默认显著性结论。

ICIR：`icir_raw = ic_mean / ic_std`，不年化。兼容字段 `icir` 暂时保留同值。多空诊断中的 `mean_over_std_raw` 同样不年化，旧 `sharpe` 字段仅为兼容字段，不能直接与年化 Sharpe 比较。

年度 IC：`yearly_ic` 直接按因子日 `trade_date` 所在自然年汇总已经计算好的每日 IC，不重复计算横截面相关。主要输出为 `yearly_ic_stats_spearman.csv`、可选的 Pearson 表，以及 `yearly_mean_ic_spearman.png`/`yearly_mean_ic_pearson.png`。即使 h 日收益退出日跨年，仍按因子日所在年份归属。`yearly_ic_min_days` 默认 60；有效天数不足时保留该行及 `valid_days`，统计值置为 `NaN`。`yearly_ic_include_partial_year=True` 默认保留不完整年份；完整性采用该年度样本是否同时覆盖 1 月和 12 月判断，并写入 `is_complete_year`。

分组收益：每天按因子从低到高分 10 组，组内股票等权，之后对时间求均值。

多空收益：原始序列仍是每个因子日的 `G10_h - G1_h`，保存在 `daily_long_short_returns`。对 `h>1`，这些是逐日重叠的 h 日远期收益，不能直接逐日复利解释为组合净值。

多空诊断曲线：`long_short_curve.png` 先分别将 G10 和 G1 的 h 日收益转换为日等效收益 `(1 + group_return) ** (1 / h) - 1`，再计算两组之差并累计。新表为 `daily_equivalent_long_short_returns` 和 `cumulative_daily_equivalent_long_short_returns`。该曲线用于统一 horizon 的诊断尺度，不是考虑重叠持仓和资金分层后的真实 NAV。旧 `cumulative_long_short_returns` 继续保存原始 spread 的累计和，仅用于兼容历史下游。

最大回撤：1D 可输出 `diagnostic_max_drawdown`；`h>1` 的重叠远期收益不对应单一可实现组合，因此该字段为 `NaN`，并在 `not_applicable_reason` 标记 `overlapping_forward_returns`。旧 `max_drawdown` 仍保留历史算法结果作为兼容字段，但报告不再展示它。
这里的 `G10 - G1` 是固定方向 spread 诊断，不会自动判断因子正负方向；若因子方向未知，应同时查看 G1 和 G10 的收益、暴露与换手。

分组收益：同时输出全样本 10 组 × 多 horizon 平均收益合并图，以及 1D、5D、10D、20D 各自单独一张 10 组累计收益线图。线图会先把 h 日未来收益转换为日均等价收益 `(1 + group_return) ** (1 / h) - 1`，再按复利生成净值序列，避免把重叠的 h 日收益当成每日收益重复复利。G1 为因子值最低组，G10 为因子值最高组。

分层收益：按 `group_return_windows` 分别统计最近 6 个月、1 年、3 年、5 年的 10 组收益，每个窗口一张图，图内同时展示 1D、5D、10D、20D。
## Company Diagnostics 正式诊断 JSON

这部分是公司侧正式诊断输出，使用 `BacktestConfig(diagnostics=CompanyDiagnosticsConfig(...))` 控制，默认关闭。它不同于 `HandoffConfig` 生成的第一轮验收占位文件：正式 diagnostics 只在实际计算成功时写 `status="computed"` 的 JSON；没有计算的文件不会生成。

diagnostics 只保存在对应不可变 run 中；`latest.json` 会指向最新成功 run，不再复制第二份：

```text
<output_root>/<factor_name>/runs/<run_time>/diagnostics/
```

可能生成的文件：

```text
spanning.json
crowding.json
mechanism_consistency.json
diversity.json
```

### 输入数据格式

`production_book` 和 `peer_book` 使用长表，等价于多张因子宽表按 `factor_id` 叠在一起：

```csv
date,symbol,factor_id,value
2026-01-02,000001.XSHE,rev_20d_v3,0.32
2026-01-02,000002.XSHE,rev_20d_v3,-0.18
2026-01-02,000001.XSHE,liq_amihud_v2,1.41
```

列名兼容：

```text
date 或 trade_date
symbol 或 stock_id 或 asset
value 或 factor_value 或 factor
factor_id
```

`regime` 使用布尔宽表：

```csv
date,bull,bear,high_vol,low_vol
2026-01-02,true,false,false,true
2026-01-05,true,false,true,false
```

`production_book` 用于 `spanning.json`，代表生产/上线因子库；`peer_book` 用于 `crowding.json` 和 `diversity.json`，可以比 production 更宽，包含 promoted、research 等 peer 因子。`factor_id` 必须是稳定字符串。


### 计算口径

- `crowding.max_abs_rankcorr`：候选因子与每个 peer 每天做截面 RankCorr，取绝对值后按交易日均值，再在 peer 间取最大。
- `crowding.topk_overlap`：用最相似 peer，分别比较候选和 peer 的最高 K、最低 K 股票，取两端 overlap 的平均。
- `diversity.max_similarity_to_book`：只基于 `all` pool，使用和 crowding 相同的 mean abs RankCorr 口径。
- `spanning.incremental_ic`：候选因子先对最相关 production 因子做迭代等权截面 OLS 残差化，再用最终 residual 计算 IC。
- `spanning.incremental_r2`：用已选 production 因子作为 baseline，再加入 residual candidate，计算日度截面 R2 提升后取均值。
- `mechanism_consistency.group_monotonicity`：G1-G10 平均分组收益和组号的 Spearman 相关。
- `mechanism_consistency.regime_detail`：每个固定 regime 标签内单独计算 IC；标签可以重叠。当 `hypothesis_direction="unknown"` 时，方向匹配相关字段写 `null`。

正式 diagnostics 遵守公司侧固定 schema：只输出 `all`、`hs300_pool`、`zz1000_pool`、`zz2000_pool` 四个 pool 的交集；`spanning.json` 和 `mechanism_consistency.json` 只输出 `"1"`、`"5"`、`"10"`、`"20"` 四个 horizon。其他普通回测 pool、external return 或自定义 horizon 可以继续用于常规报告，但不会写入这四类正式 JSON。

### 写文件规则

- 没有输入或无法计算的诊断文件不会生成。
- 不写 `pending`、不写空占位、不用 `0` 或 `null` 填补缺失 pool/horizon。
- 每个已生成文件都会包含 `status="computed"` 和 `meta`。
- `crowding` 按 pool 输出；`diversity` 只基于 `all` pool 输出一份；`spanning` 和 `mechanism_consistency` 按 pool 和 horizon 输出。
